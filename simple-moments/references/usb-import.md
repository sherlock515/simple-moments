# Mac 数据线读取

随附 `scripts/usb_photos.m` 使用 macOS ImageCaptureCore 枚举连接设备的媒体并下载副本，不依赖固定设备名或用户目录。只支持系统通过该框架暴露的相机设备。不要运行旧任务里硬编码日期、路径或设备名的程序。

首次在当前机器使用时编译到任务临时目录（示例路径需替换）：

```sh
xcrun clang -fobjc-arc -framework Foundation -framework ImageCaptureCore /absolute/skill/scripts/usb_photos.m -o /absolute/task/usb-photos
/absolute/task/usb-photos --help
```

用全新输出目录执行。参数依次是日期、时区、新目录、可选设备名称。程序先扫描设备；未指定名称且有多个相机设备时返回错误和设备名称，不自行选设备。

```sh
/absolute/task/usb-photos 2026-10-07 Asia/Shanghai /absolute/task/原图
```

目录中 `import-manifest.json` 包含源名称、相对路径、设备时间、下载路径、文件大小和状态。按索引为每个文件单独建子目录，避免同名覆盖。实际文件名以下载回调为准。退出码非零表示失败或部分失败；检查清单中的逐项状态，成功项可继续处理，不盲目重复导入。

## 日期范围与完整性

程序读取目标日期及前后各一天的静态图片候选，并保留同目录、同 stem 的 MOV/MP4 配对。这个缓冲用于时区跨日复核，不能直接将全部导入文件当成目标日期。读取后从 EXIF 检查 DateTimeOriginal、OffsetTimeOriginal 等真实拍摄信息，确定最终候选；用户时区已知时在该时区比较日期。

设备 creationDate 不保证等于拍摄日期。脚本记录没有设备日期的图片，但不自动全库下载。若元数据缺失、设备日期与 EXIF 显著不符、目标照片为空或明显不完整，不能声称查全或当天没有照片。报告实际观察，尝试现有照片图库/系统“图像捕捉”中可见的来源，或请用户指明已有照片文件夹；不要自动下载整个图库。

本脚本不处理视频独立投稿、设备上未暴露的云端原片或按相册名检索；不要把这些情况伪装成成功。选择实况图片时同时保留配对记录，同名配对只作为候选，必要时核对媒体内容标识符。

## 出错时

- 找不到设备：如实说未检测到可读取的设备，先请用户检查数据线连接。只根据实际状态提示下一步。
- 打开会话失败：显示错误含义；如果系统明确要求授权，再提示相应操作。
- 缺少编译工具：优先使用已经安装的兼容导入工具或系统图像捕捉，不自动安装大型工具链。
- 超时、断连、部分下载失败：查看清单并保留成功文件，继续处理可用图片。当前脚本不支持按失败清单定向重试；不要为了补几张而重新全量下载。只有已有其他工具支持指定失败文件时才定向重试一次，否则说明缺失项。不要把部分成功说成全部完成。

Apple 的导入背景说明：https://support.apple.com/en-us/120267 。这不是要求用户阅读或预先完成的操作清单。
